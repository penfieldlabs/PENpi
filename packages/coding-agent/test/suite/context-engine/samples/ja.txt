コンテキストウィンドウとは、大規模言語モデルが一回のリクエストで処理できるトークン数の上限のことです。会話が長くなると、クライアントはどの内容をウィンドウに残し、どの内容を外に出すかを決めなければなりません。従来の方法では、モデル自身に要約を書かせ、古いメッセージをその要約で置き換えていました。しかし要約には重要な細部が抜け落ちることがあり、さらに要約を作るたびに追加のモデル呼び出しが必要になるため、遅くて費用もかかります。

もう一つの方法は先入れ先出しです。最も古いメッセージから順にウィンドウを離れますが、完全な記録はディスクに保存されたままなので、必要になれば検索ツールで読み直すことができます。プロンプトキャッシュを有効に使うためには、ウィンドウの始点をリクエストのたびに動かしてはいけません。高水位に達したときに一度だけ低水位まで進め、次に高水位を超えるまでは固定しておくのが望ましいのです。

トークン数の見積もりも難しい問題です。多くのクライアントは文字数を四で割って見積もりますが、これは英語ではおおむね妥当でも、日本語や中国語では大きく過小評価になります。圧縮された JSON や Base64 のデータ、インデントの多いソースコードでも、誤差の方向と大きさはそれぞれ異なります。そのため、サービス側が実際に返す使用量で見積もりを校正し、モデルごとに別々に校正するのが望ましいでしょう。
